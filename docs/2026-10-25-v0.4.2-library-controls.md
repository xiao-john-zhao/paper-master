# v0.4.2：来源、缓存、分析状态与图谱（2026-10-25）

## 五项改动

1. **模型与时间**：结果下拉项和详情分别显示服务、型号、总结/摘录时间、人工修订次数与最近修改时间。历史未记录的型号明确标为未知；legacy 记录时间不冒充真实总结时间。新 LM Studio 结果记录实际响应模型；新 Codex 请求从有界进程头部读取型号，正文、提示词和 reasoning 不写入诊断日志。
2. **缓存位置与搬运**：Diagnostics 新增“更改位置 / 读取搬运的缓存”。选择新目录后复制、读取校验、合并缺失结果并导出当前数据库，最后原子切换位置指针；原目录不删除。手动搬运后可选择新目录继续使用。指针为数据库旁的 `cache-location.json`，与应用版本无关，丢失数据库也能定位自定义缓存。
3. **未分析内容**：迁移前 433 篇论文当前只有原文摘录，却被标记为 analyzed；304 篇当前摘录包含“未可靠识别”等占位。迁移 10 清除未编辑 extractive 版本的系统占位，保留模型与人工结果，纠正完成状态。补上 PDF 中 `C ONCLUSION`、分散字母、小节编号、“结论与未来工作”等识别，在参考文献、附录、致谢前结束；399 篇待分析论文回填可靠结论原文。摘录页面明确为非模型待分析，仅展示实际原文，不伪造方法/创新/贡献。
4. **关键词复选**：侧栏显示完整关键词词表、全库计数和复选框，多选按交集筛选，支持搜索叠加与清除所选。筛选结果不再用来重建词表，勾选后不会消失。后端兼容旧 `tag` 并新增 `tags[]`，保持规范别名匹配。
5. **关系图缩放**：20%–500% 只投影节点和连线坐标，字号、节点半径与交互区域保持不变；支持平移与重置。三个网络视图共用该行为，外层 SVG 不再整体 scale。

## 本地分析补齐

用户追加要求：完成应用内修改后启动 LM Studio 本地补齐。资料库“补齐待分析”按当前筛选排队；后端跳过已有完整模型结果、重复 ID 和在途任务，单独统计无文本论文。每篇配置快照与队列状态在同一事务保存，`analysis-queue-settings:<paper_id>` 固定服务/模型；切换交互设置不会把本地批次改为在线请求。

维护入口 `paper-master.exe --queue-missing-local` 要求当前保存 LM Studio 配置，将全部待补齐论文加入持久队列；打开 GUI 后串行运行，重启恢复中断任务。真实模型输出通过中文、JSON Schema、原文证据与标签校验后才保存；失败不会用演示模型或摘录冒充成功。模型响应拒绝原文摘录系统占位文字。
