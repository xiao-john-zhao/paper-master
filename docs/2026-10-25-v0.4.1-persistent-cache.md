# v0.4.1 论文结果持久缓存（2026-10-25）

本次修复针对更新、切换启动入口或库记录缺失后看不到已整理论文的问题。新版本保持原 SQLite 库，并增加独立、可读的逐篇 JSON 恢复文件。

## 使用方式

- 统一入口：`application/paper-master.exe`；同时保留 `application/paper-master-v0.4.1.exe`。
- 固定缓存：`%APPDATA%/app.papermaster.desktop/library-cache/v1/`，不随应用版本、EXE 名称或启动目录变化。
- 论文详情继续提供元数据编辑、分析逐字段编辑、版本切换和恢复原始生成内容。每次保存自动更新数据库及文件缓存。
- Diagnostics → 论文文件缓存：打开文件夹、立即同步、从缓存补回缺失记录。资料库出现缓存问题时显示进入该面板的提示。
- 本地维护：`application/paper-master.exe --sync-cache`，备份数据库并生成缓存和本地状态报告；不访问模型或网络。

## 保存与恢复规则

每篇一个 JSON，包含论文信息、提取文字、所有整理版本、服务/模型信息、时间、修订号、人工编辑标记、原始生成文字和当前选择。缓存格式 `cache_schema_version: 1` 独立于应用版本。文件名使用论文 ID 的 UTF-8 十六进制编码，避免将外部 ID 当作路径。

先写临时文件、刷新到磁盘、再原子替换。保留上一份 `.json.bak`。损坏文件尝试备份并逐篇跳过；更新时另存损坏原件。未来格式不直接覆盖。用户删除的论文写入删除标记，备份同时保存删除标记，避免下次启动从旧备份复活。

迁移 9 增加 `library_cache_pending` 和数据库触发器。导入、后台分析、版本切换/编辑/还原、元数据编辑和删除均在 SQLite 事务中登记待同步记录。所有应用存储连接统一在提交后导出，文件失败保留数据库和待同步记录，并显示错误，重试时读取最新数据库内容。

启动顺序：先导出旧版应用留下的待同步写入/删除，再从缓存补回缺失论文或分析版本，最后初始化没有缓存的记录。已有数据库字段、修订内容及当前选择优先；已有论文缺少分析时可恢复缓存的当前结果。恢复使用独立事务并重建正常搜索投影，不访问或改动源 PDF。

历史二进制继续使用同一应用标识和 SQLite 目录；它们自身不包含新 JSON 恢复代码。v0.4.1 及后续兼容版本可直接读取缓存。浏览器预览仍是演示库。换电脑需要单独复制应用数据目录，并按需重新关联原 PDF。

版本源同步为 0.4.1：package.json、Cargo.toml、tauri.conf.json、前端 appConfig 和 Cargo.lock 项目条目。`scripts/Check-Version.ps1` 校验一致性，Build-Local 构建前执行校验并保留原入口及版本化 EXE。下一维护目标 v0.4.2。

上一版本入口保存在本机 `handoff/release-backups/paper-master-v0.4.0-before-cache.exe`。数据库快照位于应用数据目录 `paper-master-before-v0.4.1-*.db`。回退应用程序继续使用共享库；不要直接用旧数据库覆盖较新的个人编辑。

个人缓存、数据库、校验明细、二进制和发布清单不提交 Git，也不混入源码迁移包。缓存不保存账号、API 设置、学校凭据、完整提示词或 reasoning，诊断日志不保存论文内容。
